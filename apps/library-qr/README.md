# library-qr —— 生态示例：合肥市中心图书馆读者证（动态码）

> 一个真实的"用这套工具链解决现实问题"的完整案例：把手上的 OPPO Watch S 变成
> 合肥市中心图书馆的读者证，过闸机扫码进馆。**本例演示三层能力叠加：侧载安装 →
> 动态数据 → 离线算法**。也给后来者一个思考方向：这套侧载生态能承载的真实应用，
> 远不止"Hello World"。

## 它解决什么问题

进图书馆要刷**动态读者证二维码**（官方渠道只有微信小程序，手机掏出来排队很尴尬）。
手表戴在手腕上，抬手就是码——但它得是**活的**：码文内嵌生成时刻，过几秒就失效。

这个应用的完整旅程（对后来者最有价值的部分是这条弯路记录）：

| 阶段 | 平台 | 结果 |
|---|---|---|
| 2026-06 初版 | Wear OS（安卓手表，Android 工程 LibraryWatchApp） | 防息屏/NFC 拦截/步数自动关闸全解决，**卡在闸机不认码**，工程源码后被清理，仅存 APK 与交接文档 |
| 2026-10 复盘 | PC 接口实验 | 反编译 APK 还原完整鉴权链；**130+ 样本受控实验**摸清码文规律（见下） |
| 2026-10 移植 | **Glyphix OS（本项目工具链）** | 全新 JS 应用，双模自适应，侧载上表运行 ✅ |

## 核心研究发现：码文是可离线生成的

130+ 样本交叉验证（6 月与 10 月多日取样）得到的码文结构：

```
JYB + DD + HHMMSS + 0000 + 尾号
       │     │        │      └─ 服务端随机数 1~6（同一秒观测到 1 和 6，非时间函数）
       │     │        └─ 130+ 样本恒为 0000（含义未知，保持常量）
       │     └─ 生成时刻（北京时间，与服务器钟无可感知偏差）
       └─ 当日日号（6日=06、14日=14、11日=11，多日完全吻合）
```

决定性实验：同一秒连续请求两次，其余部分完全相同、仅尾号不同 → 尾号是防重放随机数；
码文其余部分是**时间的纯函数** → 手表端按秒本地生成即可，完全离线。

## 应用设计（src/main/）

- **双模自适应**：启动先离线出码（保证有显示）→ 在线拉真码成功自动切换 → 连续失败 2 次
  降级离线、每 10 周期重试。离线期间每 10 个周期校准一次时钟偏差（存 storage，下次沿用）
- **在线模式**（可选）：`@system.cipher.hash` 原生 MD5 签名 → `@system.fetch` 取 JWT →
  取官方接口实时码。**个人凭据在 `src/main/config.js`，发布版已清空**——填你自己的才能用在线模式
- **圆屏二维码工程**：码体 370px，四角尖溢出圆边 ~1.6 模块——三个定位角的中心扫描线
  （1:1:3:1:1）完整在圆内即可解码，右下数据角由 L 级纠错兜底；识别不佳的回退值写在注释里
- **AMOLED 省电**：长按切换正/反色（黑底白码），选择存 storage 记忆
  ⚠️ v1.8.0 教训：qrcode 组件上的动态 class 绑定会导致不渲染——正反色必须双元素 if 切换 + 静态类
- **亮屏心跳**：每 15s `@system.brightness` 点屏，对抗翻腕息屏（等价于安卓版的唤醒广播）

## 运行

1. 构建（或直接用 `dist/bundle.pkg`）→ 瑰元助手侧载（仓库根 README 第 4 步）
2. PurrLaunch 列表点「合肥读者证」→ 白底二维码，每 3 秒按当前时刻重新生成
3. 要用在线模式：编辑 `src/main/config.js` 填入你自己的 `openid` / `libToken`，重新构建

## ⚠️ 使用边界

- 码文结构来自对**自己读者账号**的观测，仅供本人读者证使用；
  请勿用于伪造他人凭证或规避门禁校验——那既违反场馆规则也可能违法
- 不要把你的 `openid` / `libToken` 提交到任何公开仓库
- 保存的二维码 PNG 几秒即失效，别截图进场

## 生态思考

这个例子想说明的是：当"构建 + 侧载 + 图标注册"成为标准流水线之后，
手表应用的开发门槛就只剩**业务本身**。读者证、门禁卡、会议签到、库存盘点……
任何"小屏幕 + 动态码/动态信息"的场景，都可以用 `apps/qrwatch/` 作为骨架
（换 `qr-data.js`）、用 `@system.fetch` 接数据、用本仓库的流程装进手表。
欢迎以此为起点贡献更多 `apps/` 示例。
